## 목적
이 프로젝트는 Docker·DevOps 공부가 목적이다. 명령어와 출력만이 아니라 "왜 이렇게 동작하는지", "왜 이렇게 정했는지"를 Notion에 남겨 다시 볼 수 있는 학습 자료와 포트폴리오 근거로 만든다.

## 규칙 / 변경 내용
- [확정] Notion `프로젝트 / minecraft-devops` 아래에 페이지 2개 추가
  - **개념 정리**: 주제 1개 = 하위 페이지 1개. 원리를 설명
  - **작업 회고**: 이슈 1개 = 하위 페이지 1개. 목표, 결정, 과정, 배운 점
- [확정] 기존 페이지 역할은 유지
  - 지식 노트 = 명령어 치트시트, 원본 로그 = 날짜별 명령·출력, 트러블슈팅 = 문제 1개
  - 각 페이지는 서로 링크한다
- [확정] 시점: `/task` Phase 7에서 작성
  - feature·bug 이슈는 작업 회고 필수
  - docs·chore 이슈는 새로 배운 게 있을 때만
  - 새로 다룬 개념은 개념 정리 페이지를 만들고, 이미 있으면 덧붙인다
- [확정] 공통 규칙은 기존과 같음: 한국어, 이모지 금지, 기존 내용은 지우지 않고 추가

### 개념 정리 형식 (제목: 주제 이름)
- 맨 위 한 줄: `요약: …`
- 왜 필요한가: 어떤 문제를 푸는지
- 어떻게 동작하나: 흐름도(텍스트 그림 또는 mermaid) + 설명
- 이 프로젝트에서는: 실제 설정·명령 예시
- 헷갈리기 쉬운 점
- 더 볼 것: 공식 문서 링크
- 관련: 작업 회고, 트러블슈팅, 지식 노트 링크

### 작업 회고 형식 (제목: `#N <이슈 제목>`)
- 맨 위 한 줄: `결과: … (날짜, PR #)`
- 목표
- 결정과 이유: `| 결정 | 고른 것 | 다른 선택지 | 이유 |`
- 과정: 단계별 핵심 명령. 자세한 출력은 원본 로그 링크
- 막힌 것: 트러블슈팅 링크 (없으면 "없음")
- 배운 점: 1~5줄 + 개념 정리 링크
- 다음에 할 것
