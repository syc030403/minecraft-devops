# 기획 파일

이슈 하나마다 기획 파일 하나. `/issue`가 빈 파일을 만들고, `/plan`이 채우고, `/task`가 갱신한다.
기획 파일은 코드와 같은 PR로 `develop`에 들어간다.

- 파일 이름: `<이슈번호>-<영어-소문자-설명>.md`
- 브랜치 `feature/12-world-backup` → `docs/plan/12-world-backup.md`
- 공개 저장소다. IP·실제 포트·비밀값은 쓰지 않고 "`CLAUDE.local.md` 참고" 또는 `.env` 키 이름으로 적는다.

## 틀

```markdown
# #12 월드 백업 자동화

- 이슈: #12
- 브랜치: `feature/12-world-backup`
- 종류: feature · 영역: area:backup
- 선행: 없음 / #11
- 함께 나눈 이슈: 없음

## 목적
이 작업이 운영(또는 플레이어)에게 주는 것

## 규칙 / 변경 내용
- [확정] ...
- [임시] ... (`.env` 키: `BACKUP_KEEP`)

## 수용 기준
- [ ] 성공: ...
- [ ] 실패·예외: ...
- [ ] 경계: ...

## 지켜야 할 규칙
- verification.md 중 이 작업이 건드리는 항목 (V1, V8 …)
- 관련 기존 결정 (decisions.md)

## 영향 범위 (예상)
- compose / 스크립트 / 설정(.env.example) / 테스트 / 문서

## 확인 방법
- 자동: docker compose config, shellcheck, pytest, 추가할 테스트
- 직접: 서버에서 확인할 것

## 범위 밖
- ...

## 이 기획에서 내린 결정
| 결정 | 이유 | decisions.md |
| --- | --- | --- |

## 진행 기록
- 2026-11-20 빈 기획 파일 생성 (/issue)
- 2026-11-20 기획 작성 (/plan)
- 2026-11-21 구현 (/task)
```

## 빈 기획 파일

`/issue`가 만드는 형태. 머리(이슈·브랜치·종류·선행)만 채우고 각 절에는 `_(작성 전 — /plan)_`을 둔다.
`/plan`과 `/task`는 이 표시로 "아직 비어 있음"을 알아본다.

```markdown
# #12 월드 백업 자동화

- 이슈: #12
- 브랜치: `feature/12-world-backup`
- 종류: feature · 영역: area:backup
- 선행: 없음
- 함께 나눈 이슈: 없음

_(작성 전 — /plan)_
```
